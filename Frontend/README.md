# NeuroScan AI Frontend

## Overview

This is the standalone, TypeScript-based Vite app that powers the NeuroScan AI user experience. It bundles a React 18 single-page application with TanStack Query, React Router v6, Recharts, Lucide icons, Sonner toasts, and Tailwind CSS/Tailwind Merge helpers. The UI is shaped around a secure workspace (protected routes, token-based auth) that lets physicians upload MRI series, review scan libraries, inspect volumetric renders, and download AI-generated reports.

## Getting started

1. Install dependencies with `npm install` from the `Frontend` directory (the project uses npm + Vite; Node.js 18+ is recommended).
2. Copy any required `.env` variables if you eventually parameterize `API_BASE_URL` (the code currently points at `http://localhost:8000/api`).
3. Run `npm run dev -- --host 0.0.0.0` for local development, `npm run build` to create an optimized bundle, or `npm run preview` to serve the production build locally.
4. The `build_output.log` is generated by the latest build run and can be inspected for verbose output; you can delete it before committing if needed.

## Available scripts

- `npm run dev` – start Vite in dev mode (hot reload + React fast-refresh).
- `npm run build` – create a production build.
- `npm run build:dev` – production build using the `development` mode (handy for debugging build-only logic).
- `npm run preview` – serve the production build locally.
- `npm run lint` – run ESLint across the repo.
- `npm run test` – run Vitest once; `npm run test:watch` watches for changes.

## Project layout

- `public/` – static assets (favicon, Open Graph image).
- `src/main.tsx` + `src/index.css` – mount point, global Tailwind + CSS variable themes, and font imports.
- `src/App.tsx` – wraps the app in React Query, tooltip contexts, authentication provider, and renders routes inside `AppLayout`.
- `src/lib/` – shared helpers, API clients, and the `APP_CONFIG` object that drives navigation, text, and labels across the experience.
- `src/components/` – reusable pieces grouped by domain:
  - `auth/` – `AuthContext` + hook for token persistence and session validation.
  - `layout/` – `AppLayout` + `AppSidebar` for the left-hand nav, top bar search, user menu, and responsive content container.
  - `dashboard/` – stat cards, recent scans table, and Recharts volume chart used on the landing dashboard.
  - `scan/` – Slice viewer canvas, vtk-powered `VolumeViewer3D`, segmentation toggles, and processing timeline for the detail view.
  - `upload/` – Drop zone that auto-detects modalities, collects patient metadata, and posts to `/api/process-mri`.
  - `ui/` – Tailwind-based wrappers around buttons, cards, dialogs, menus, tables, tabs, toasts/sonner, sliders, switches, etc.
- `src/pages/` – route screens: `Index`, `Upload`, `ScanLibrary`, `ScanDetail`, `Reports`, `Settings`, `Login`, `Register`, plus `NotFound`.
- `src/hooks/` – helpers such as `useScans` (React Query wrapper) and `useConfig` (returns the static `APP_CONFIG`).
- `src/test/` – Vitest setup + placeholder tests for future coverage.

## Architectural highlights

- **Routing & protection:** `App.tsx` defines public `/login` & `/register` routes and protects the rest via `ProtectedRoute` (shows a loader until session validation finishes).
- **State & data fetching:** React Query caches scan data (`useScans`) and `lib/api.ts` handles auth headers, error handling (401 resets local storage), and `fetchScan`/`processMRI`.
- **Dashboard:** `Index.tsx` stitches `StatsCards`, `RecentScans`, and `VolumeChart`, all of which call `useScans` to show metrics, quick actions, and volumetric distributions.
- **Scan detail:** `ScanDetail.tsx` renders a tabbed view (viewer, pipeline, report) that toggles between the 2D `SliceViewer` (fetching PNGs + overlays) and the 3D `VolumeViewer3D` (dynamic `vtk.js` imports, NIfTI parsing through `nifti-reader-js`). Controls in `SegmentationControls` drive overlay visibility/opacity.
- **Upload flow:** `DropZone` supports drag-and-drop/multi-file selection, modality detection, patient metadata, and POSTs files with the authenticated token. Missing modality warnings and per-file statuses provide immediate feedback.
- **Shared config:** `APP_CONFIG` centralizes the sidebar, labels, placeholders, and copy so that UI text & nav items stay synchronized.

## Styling & themes

- Tailwind 3 with `tailwind.config.ts` + `postcss.config.js` provides the CSS toolchain.
- `src/index.css` defines design tokens for light/dark themes and adds custom utilities (medical gradients, sidebar gradient, overlay helpers).
- `lib/utils.cn` wraps utility classes with `clsx` + `tailwind-merge` to keep class strings tidy.

## API & backend expectations

- The frontend targets `http://localhost:8000/api`. Key endpoints:
  - `POST /process-mri` – uploads MRI files + metadata (authorization via bearer token stored in `localStorage`).
  - `GET /scans`, `/scans/:id`, `/scans/:id/slice/:idx`, `/scans/:id/segmentation`, `/scans/:id/download/:modality`, `/scans/:id/download/segmentation`.
  - `PUT/DELETE /scans/:id` – used by RecentScans/ScanLibrary edit/delete actions.
- `AuthContext` validates tokens against `/api/auth/me`, stores user info in `localStorage`, and exposes `login`/`logout`.

## Testing & quality

- Vitest is the chosen test runner (`src/test/setup.ts` adds DOM support). Currently only the scaffolded `example.test.ts` exists; add more tests near the components they cover.
- ESLint (with `@eslint/js`, `typescript-eslint`, React plugins) enforces code style; run `npm run lint` before commits.

## Deployment notes

- `npm run build` outputs to Vite’s `dist/` folder. You can deploy that folder to any static host (Netlify, Vercel, S3 + CloudFront, etc.).
- Because the app depends on the local backend `http://localhost:8000/api`, ensure your production deployment rewrites API requests to the real service (or proxy via env-configured `API_BASE_URL`).
- `API_BASE_URL` is hard-coded in `src/lib/api.ts`; swap it for a deploy-time value (env var or proxy) when you point the frontend at a real backend host.

## Troubleshooting & next steps

- **Token resets:** if API calls return 401, `lib/api` clears the session and redirects to `/login`.
- **Missing segmentation overlays:** check that `/scans/:id/segmentation` returns PNG masks with separate R/G/B channels.
- **Performance:** `VolumeViewer3D` dynamically imports heavyweight vtk bundles; caching or preloading may be required for production.
- **Resources:** expand `src/test` and add integration tests for upload & scan views once the backend is stable.
